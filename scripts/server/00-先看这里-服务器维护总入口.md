# 服务器维护总入口

目录位置：

```text
D:\kaifa\_tmp\class-platform\服务器维护和脚本
```

这个目录已经整理好了当前服务器维护会用到的核心脚本和说明，后续直接看这里即可。

## 1. 最常用文件

优先看这 4 个：

- `FINAL_SERVER_MAINTENANCE_RUNBOOK.md`
- `MAINTENANCE.md`
- `safe-maintenance.sh`
- `install-maintenance-cron.sh`

作用分别是：

- `FINAL_SERVER_MAINTENANCE_RUNBOOK.md`
  - 最终执行版文档
  - 按你的服务器目录和 BaoTa 终端方式整理
  - 后续维护直接按这个文件执行

- `MAINTENANCE.md`
  - 精简说明版
  - 适合快速查看脚本能力和开关

- `safe-maintenance.sh`
  - 安全维护主脚本
  - 默认只清理安全项
  - 不动数据库、不动 Docker 卷、不动上传目录

- `install-maintenance-cron.sh`
  - 安装定时维护任务
  - 每日自动安全维护
  - 每周自动报告

## 2. 当前推荐的日常用法

### 2.1 只看报告

```bash
cd /www/wwwroot/teaching-platform
bash ./scripts/server/safe-maintenance.sh --report-only
```

### 2.2 预演清理，但不删除

```bash
cd /www/wwwroot/teaching-platform
bash ./scripts/server/safe-maintenance.sh --dry-run
```

### 2.3 正式执行一轮安全维护

```bash
cd /www/wwwroot/teaching-platform
bash ./scripts/server/safe-maintenance.sh
```

### 2.4 安装每日定时维护

```bash
cd /www/wwwroot/teaching-platform
bash ./scripts/server/install-maintenance-cron.sh
```

### 2.5 如果还要加每周旧备份清理

```bash
cd /www/wwwroot/teaching-platform
bash ./scripts/server/install-maintenance-cron.sh --enable-panel-backup-cleanup
```

## 3. 当前已确认的维护原则

默认不会做这些危险动作：

- 不删除 MySQL 数据目录
- 不删除 Docker volumes
- 不删除站点上传目录
- 不删除业务源码
- 不默认 drop cache
- 不默认 refresh swap

默认会做这些安全动作：

- 清理 Docker 无用镜像和构建缓存
- 清理 journal 历史日志
- 清理 `/tmp`、`/var/tmp`
- 清理 root 的 pip/npm/yarn 缓存
- 清理教学平台旧部署包

补充一条这轮真实验证后的新原则：

- 磁盘突然飙高时，先查 `du -xhd1 / | sort -h`
- 先看 `/.Recycle_bin` 和 `/www/.Recycle_bin`
- 回收站只做手动显式清理，不进默认 cron

## 4. 当前服务器状态结论

这轮检查后的结论：

- 最新一轮清空回收站后，磁盘占用大约在 `46%`
- 当前可用空间已经明显回升，暂时不属于紧急告警
- 备份目录 `/www/backup` 体积不大，不是主要压力源
- 教学平台本身不是当前服务器磁盘的大头
- 现在不需要激进清理业务目录

后续新增一条已经验证有效的经验：

- 真正的大头可能不在 `/www`
- 这次实测最大空间来源是 `/.Recycle_bin`
- 清空回收站后，磁盘占用从大约 `80%` 下降到大约 `46%`
- 这个动作已经写进 `safe-maintenance.sh` 和 `FINAL_SERVER_MAINTENANCE_RUNBOOK.md`
